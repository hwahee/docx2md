# docx2md

`.docx` 문서를 기계적으로 Markdown으로 옮겨 git에서 문서 내용의 변화를 diff로 볼 수 있게 하는 CLI입니다.

- **진실의 원천은 `.docx`입니다.** Markdown은 `.docx`에서 생성되는 보기 전용 사본이고, 직접 고치지 않습니다.
- **같은 `.docx`는 언제나 같은 Markdown이 됩니다.** 시각·플랫폼·실행 순서에 따라 출력이 달라지지 않으므로, diff에는
  문서가 실제로 바뀐 부분만 나옵니다.
- **diff가 작게 나오도록 씁니다.** 글꼴·크기·색 같은 서식은 버리고 구조(제목, 목록, 표, 강조, 링크, 그림)만 남깁니다.
  표의 칸을 같은 폭으로 맞추지 않고(한 칸이 길어져도 열 전체가 바뀌지 않음), Word가 수시로 다시 만드는 목차의
  책갈피 링크는 글자만 남깁니다.

## 요구 사항

| 런타임 | 버전                                                |
| ------ | --------------------------------------------------- |
| Bun    | 1.4 이상 (이 저장소의 개발 버전은 **1.4.4**로 고정) |

개발 버전은 `package.json` 한 곳에만 적혀 있습니다(`packageManager`, `engines.node`). CI도 이 값을 그대로 읽습니다.

## 설치

쓰려는 저장소에서 GitHub 의존성으로 설치합니다.

```bash
bun add -d github:hwahee/docx2md
```

명령은 `bun run docx2md <명령>`으로 실행합니다. (`bunx docx2md`는 쓰지 마세요. 로컬에 없으면 npm에서 같은 이름의
다른 패키지를 받아 실행할 수 있습니다.)

## 명령

| 명령                   | 하는 일                                                                                          |
| ---------------------- | ------------------------------------------------------------------------------------------------ |
| `docx2md` (= `build`)  | 선택된 `.docx`를 모두 변환하고, 원본이 사라진 생성 파일을 지웁니다                               |
| `docx2md watch`        | `build` 후 파일이 바뀔 때마다 다시 변환합니다 (새 폴더, 이름 변경, 삭제 포함. Ctrl+C로 종료)     |
| `docx2md check`        | 아무것도 바꾸지 않고, Markdown이 없거나 낡았으면 종료 코드 1 (CI용)                              |
| `docx2md staged`       | 스테이징된 `.docx`만 변환해 그 Markdown을 함께 스테이징합니다 (pre-commit 훅용)                  |
| `docx2md migrate`      | docx2md 업데이트로 출력 형식이 바뀌었을 때, 그 변화만 담은 커밋을 준비합니다 ([아래](#업데이트)) |
| `--help` / `--version` |                                                                                                  |

종료 코드: `0` 성공, `1` 변환 실패 또는 `check`가 낡은 파일을 찾음, `2` 잘못된 명령·옵션·설정 파일.

### 옵션

| 옵션                   | 설정 파일 키 | 기본값         | 설명                                                                           |
| ---------------------- | ------------ | -------------- | ------------------------------------------------------------------------------ |
| `-i, --include <glob>` | `include`    | `**/*.docx`    | 변환할 파일. 여러 번 줄 수 있음                                                |
| `-e, --exclude <glob>` | `exclude`    | 없음           | 뺄 파일. 여러 번 줄 수 있음                                                    |
| `-o, --out-dir <dir>`  | `outDir`     | `.docx` 옆     | Markdown을 이 폴더 아래에 원본과 같은 폴더 구조로 씁니다                       |
| `--images <mode>`      | `images`     | `extract`      | `extract`: 그림을 파일로 저장해 링크 / `omit`: 그림 파일 없이 내용 해시만 남김 |
| `-c, --config <file>`  |              | 아래 설정 파일 | 설정 파일 경로                                                                 |

`node_modules`, 숨김 폴더(`.git` 등), Word의 잠금 파일(`~$문서.docx`, 문서를 열어 둔 동안 생김)은 설정과 상관없이
언제나 건너뜁니다. glob과 경로는 명령을 실행한 폴더(보통 저장소 루트) 기준이고 `/`로 씁니다.

### 설정 파일

실행한 폴더에 `docx2md.config.json`이 있으면 읽습니다(없어도 됩니다). 명령줄 옵션은 설정 파일의 같은 키를
**대체**합니다(합치지 않음). 모르는 키나 잘못된 값은 아무 파일도 건드리기 전에 오류로 멈춥니다.

```json
{
  "include": ["docs/**/*.docx"],
  "exclude": ["docs/drafts/**"],
  "outDir": "docs-md",
  "images": "extract"
}
```

`watch`, `staged`, `check`가 모두 같은 설정을 쓰도록, 선택 규칙은 명령줄보다 설정 파일에 두는 것을 권합니다.

## 저장소에 붙이기

`package.json`:

```json
{
  "scripts": {
    "docs:watch": "docx2md watch",
    "docs:check": "docx2md check"
  }
}
```

**커밋할 때 자동으로 맞추기 (husky)** — `.husky/pre-commit`:

```sh
bun run docx2md staged
```

`staged`는 커밋에 들어갈 `.docx`(작업 트리가 아니라 git 인덱스의 내용)를 변환해 Markdown을 스테이징하므로,
`.docx`와 그 Markdown이 언제나 같은 커밋에 들어갑니다. `.docx`를 지우면 Markdown도 지워지고, 이름을 바꾸면 따라갑니다.
변환에 실패하면 커밋이 멈춥니다. lint-staged를 함께 쓴다면 같은 훅에서 `bunx lint-staged`보다 앞에 둡니다.

**CI** — 훅을 건너뛴 커밋(`--no-verify`)을 잡으려면 CI에서 `bun run docx2md check`를 돌립니다.

**prettier를 쓰는 저장소라면** 생성된 Markdown을 `.prettierignore`에 넣으세요(예: `outDir`을 정하고 그 폴더를 무시).
prettier가 표를 다시 정렬하면 diff가 커지고, `check`가 그 파일을 낡았다고 봅니다.

## 출력

`docs/기획서.docx` → `docs/기획서.md` (`outDir`이 `docs-md`면 `docs-md/docs/기획서.md`):

```text
<!-- generated by docx2md (format 1) from "docs/기획서.docx"; edit the .docx, not this file -->

# 기획서

본문 **굵게** _기울임_ ~~취소선~~

- 항목
  - 하위 항목

| 항목 | 값 |
| --- | --- |
| 첫째<br>둘째 | 1 |

![그림 설명](기획서.assets/3473f24cf54b59a3.png)
```

- **첫 줄(헤더)**: 어느 `.docx`에서, 어느 출력 형식으로 만들었는지 적힙니다. docx2md는 이 헤더로 자기 파일을 알아봅니다.
- **그림**: `<이름>.assets/<내용 해시>.<확장자>`에 저장됩니다. 그림이 그대로면 파일 이름도 그대로라 diff가 생기지 않고,
  문서에서 빠진 그림은 지워집니다. `omit`이면 그림 파일 없이 `![설명](#<내용 해시>)`만 남아, 그림이 바뀐 것은 diff로
  보이지만 바이너리가 git에 들어가지 않습니다.
- **제목**: Word의 제목 스타일(제목 1~6, 문서 제목)을 따릅니다. 한국어 Word에서 만든 문서도 같습니다.
- **표**: 첫 행이 머리글입니다. 칸 안의 여러 문단은 `<br>`로 잇고, 병합된 칸은 빈 칸으로 채워 모양을 유지합니다.
- **줄바꿈**(Shift+Enter)은 줄 끝의 `\`로 씁니다. 눈에 보이지 않는 공백 두 칸 대신 쓰는 것입니다.
- **버리는 것**: 글꼴, 크기, 색, 밑줄, 정렬, 머리글/바닥글, 메모. 각주는 문서 끝에 목록으로 남습니다.

### 안전 규칙

- 헤더가 없는 Markdown(사람이 쓴 파일)은 **절대 덮어쓰거나 지우지 않습니다.** 예를 들어 `README.docx`의 출력 자리에
  직접 쓴 `README.md`가 있으면 그 문서의 변환은 실패로 보고되고 `README.md`는 그대로 남습니다.
- `.assets` 폴더에서는 docx2md가 만든 이름(내용 해시)의 파일만 지웁니다.
- 원본이 사라졌거나, 선택에서 빠졌거나, `outDir`이 바뀌어 자리가 옮겨진 생성 파일은 `build`/`watch`가 지웁니다.
- 변환하지 못한 `.docx`(손상, 저장 중)는 실패로 보고되고, 그 문서의 기존 Markdown은 그대로 둡니다. `watch`는 잠시 뒤
  다시 시도합니다.

## 업데이트

docx2md가 바뀌면 같은 `.docx`에서 나오는 Markdown이 달라질 수 있습니다(변환 규칙 개선, 의존성 업데이트). 그 변화가
다음 문서 수정 커밋에 섞이면 그 커밋의 diff에서 실제로 문서가 바뀐 부분을 찾기 어려워집니다. 그래서:

- **출력 형식 버전**: 생성 파일의 헤더에 `format N`이 적힙니다. 이 번호는 출력이 달라질 때만 올라갑니다. 출력이 그대로인
  업데이트는 아무 파일도 바꾸지 않습니다. 변환 의존성(mammoth, turndown)은 정확한 버전으로 고정되어 있어, 같은 docx2md
  버전이면 어느 저장소에서나 같은 출력이 나옵니다.
- **섞이지 않게 막기**: 커밋된 Markdown의 형식이 지금 docx2md와 다르면 `staged`가 그 문서의 커밋을 멈추고 `migrate`를
  안내합니다. `check`도 낡은 이유가 형식 변화라는 것을 알려 줍니다.
- **형식 변화만 담은 커밋 만들기**:

  ```bash
  bun update docx2md
  ```

  ```bash
  bun run docx2md migrate
  ```

  ```bash
  git commit -m "docx2md: regenerate for output format 2"
  ```

  `migrate`는 커밋된 `.docx`를 모두 새 형식으로 다시 변환해 스테이징합니다. 작업 중인(HEAD와 다른) `.docx`가 있으면
  그 수정이 섞이지 않도록 멈추므로, 먼저 커밋하거나 `git stash` 해 둡니다. 실행 중인 `watch`는 업데이트 후 다시 띄웁니다.

## 개발

```bash
bun install          # 의존성 + husky 훅 설치
bun run check        # prettier → eslint → tsc → knip → test (CI와 같음, pre-push 훅)
bun src/cli.ts --help
```

```
src/
├── cli.ts        # 진입점: 인자 해석, 명령 실행, 출력·종료 코드
├── config.ts     # 설정 파일 + 명령줄 옵션, 한 번에 검증
├── sources.ts    # 무엇이 원본인지 (include/exclude, 항상 건너뛰는 것), 폴더 순회
├── layout.ts     # 출력 위치, 헤더, 출력 형식 버전
├── sync.ts       # 계획(무엇이 바뀌나)과 적용(쓰기) — build/check/watch가 공유
├── git.ts        # staged, migrate
├── watch.ts      # 파일 이벤트 → 디바운스된 전체 동기화
├── convert/      # ★ 변환 파사드 — mammoth/turndown은 mammoth-adapter.ts 안에서만 import (ESLint로 강제)
└── testing/      # 테스트용 .docx 생성기, 임시 프로젝트
```

- **변환 파사드**: 나머지 코드는 `convertDocx(bytes, options)`만 압니다. 변환 라이브러리를 바꾸려면 어댑터 하나를
  새로 쓰면 됩니다. 라이브러리와 상관없이 지켜야 하는 것(그림 이름, 공백 정규화)은 `convert/core.ts`에 있습니다.
- **테스트**: 테스트마다 필요한 WordprocessingML을 직접 적어 `.docx`를 만듭니다(`src/testing/docx.ts`). 바이너리
  픽스처가 없습니다. 실제 파일 시스템·git·파일 감시를 임시 폴더에서 돌리며, `bun test` 하나로 외부 환경 없이 실행됩니다.
- **출력이 바뀌는 변경**: `src/convert/format.test.ts`가 실패합니다. `FORMAT_VERSION`(`src/layout.ts`)을 올리고, 그
  테스트에 새 해시를 더하고, 위 "출력 형식 버전" 표에 한 줄을 씁니다.
